# الاختبارات والبيانات التجريبية وبوابات الجودة

## الفحوص المعتادة

نفّذ الأوامر من جذر المستودع بعد تثبيت الاعتماديات:

```bash
composer validate --strict
composer test
composer analyse
composer lint
```

وفحوص مساعدة:

```bash
php benchmarks/basic.php
```

يشغّل `composer test` اختبارات Pest، ويحلل `composer analyse` مجلد `src/` بواسطة PHPStan، ويتحقق `composer lint` من التنسيق باستخدام Pint. نفّذ الفحوص على الـ commit وإصدار PHP المقصودين للنشر؛ نجاح فحص الصياغة أو اختبار محدد لا يغني عن المجموعة الكاملة.

## طبقات الاختبار

| الطبقة | المسار | ما الذي تغطيه |
|---|---|---|
| ثوابت الكلمات | `tests/Fixtures/words/` و`tests/Unit/Fixtures/WordComponentsFixtureTest.php` | المكونات والحركات والتصنيفات ومعرّفات القواعد والالتباس وتطبيع المدخلات. |
| ثوابت القصائد متعددة الأبيات | `tests/Fixtures/poems/multi-bayt-regression.json` | التجميع ونسب الاعتماد واختيار المرجع وأنواع العيوب وأرقام الأبيات. |
| ثوابت موسوعة الشعراء | `tests/Fixtures/poems/poetspedia-50.json` | مجموعة انحدار من 50 مدخلاً لاختبار الروي. |
| اختبارات الوحدات | `tests/Unit/` | اكتشاف المكونات والتجميع والعيوب والخيارات وربط النص وكائنات النتائج والقواعد. |
| اختبارات CLI | `tests/Feature/CliTest.php` | صيغة الأوامر والخيارات ورموز الخروج وJSON. |
| اختبارات البنية | `tests/Unit/Architecture/` | قيود مختارة على الاعتماديات وحجم الملفات. |

## سياسة بيانات الانحدار

تثبت بيانات الانحدار السلوك المتوقع حالياً؛ لكنها لا تثبت وحدها الصحة العروضية. يحتوي `known-limitations.json` على حالات معروفة يختلف فيها السلوك الحالي عن القراءة التقليدية، لتكون أي معالجة لاحقة تغييراً مقصوداً ومختبراً.

عند إضافة قاعدة جديدة:

1. أضف معرّفاً فريداً لها إلى الأثر وسجّلها في `QafyaRuleRegistry`.
2. أضف اختبار انحدار موجهاً على مستوى الكلمة أو القصيدة.
3. وثّق شروط القاعدة والاستثناءات.
4. أضف مرجعاً علمياً بالمعلومات المتاحة؛ اجتياز الاختبار ليس تصديقاً علمياً.
