# قائمة التحقق قبل الإصدار

استخدم هذه القائمة في كل إصدار، وشغّل الأوامر من نسخة المستودع نفسها التي ستضع عليها الوسم.

## بوابات آلية

```bash
composer validate --strict
composer test
composer analyse
composer lint
```

إذا توفرت بيانات مراجعة بشرية لمجموعات التحقق والاختبار، شغّل تقييمها واحفظ التقارير. لا تثبت المجموعة التي لا تحتوي سجلات متحققة دقة لغوية حتى لو كانت بنيتها صالحة.

## قبل وضع الوسم

- راجع `git diff` وقائمة الملفات المتغيرة كاملة مقارنة بالإصدار السابق.
- تحقق من تغييرات التوافق في التواقيع العامة والتعدادات وحقول JSON والقيم الافتراضية ورموز خروج CLI.
- شغّل الاختبارات كاملة وافحص مخرجات JSON للحالات المتأثرة، لا ملخص التأكيدات فقط.
- تأكد من تسجيل جميع معرّفات القواعد ومن وجود اختبارات لها.
- طابق أمثلة README والتوثيق العربي والإنجليزي مع الواجهة الفعلية.
- راجع الاعتماديات وامتدادات PHP المطلوبة في تثبيت نظيف.
- حدّث `CHANGELOG.md` بحيث تعكس التغييرات السلوكية والتوافقية بدقة.
- افصل بين نتائج بوابات جودة البرمجيات وبين ادعاءات الدقة العلمية التي تحتاج مراجعة بشرية.
- ضع الوسم بعد اجتياز البوابات المطلوبة؛ ونشر GitHub Release خطوة منفصلة إذا أردت صفحة إصدار عامة.

## بعد وضع الوسم

- تحقق من أن الوسم يشير إلى الـ commit الصحيح وأنه موجود على المستودع البعيد.
- تحقق من ظهور ملاحظات الإصدار والأرشيف وتعليمات التثبيت.
- اختبر تثبيت الوسم المنشور داخل مشروع مؤقت ونظيف.
